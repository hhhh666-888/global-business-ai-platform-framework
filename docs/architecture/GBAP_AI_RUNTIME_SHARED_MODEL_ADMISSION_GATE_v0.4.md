## 4. Idempotent bounded cleanup

Cleanup must never use broad provider deletion or database shortcuts.

For the exact admitted provider/instance:

```text
GET /providers/{provider}/instances
-> target absent
     PASS
     alreadyAbsent=true
-> target present
     DELETE /providers/{provider}/instances
     {"instances":["<exact instance id or name>"]}
     require result PASS
-> auth failure / unexpected provider failure / mismatched state
     FAIL
```

The same rule applies to admission rollback and post-bake-off cleanup.

Already-absent means only that the exact bounded instance is gone. It must not
suppress unrelated errors.
